## 기능별 정보와 업무 규칙

### R01 로그인 및 계정 이용

- **사용자 동작**: 로그인

- **필요한 결과**: 인증 성공 여부, 사용자 식별 정보·이름·역할·기관·이용 범위

#### 로그인 상태 확인

- **사용자 동작**: 로그인 상태 확인
- **입력 정보**: 현재 로그인 식별 정보
- **필요한 결과**: 유지 또는 만료 여부, 현재 사용자 정보

#### 로그아웃

- **사용자 동작**: 로그아웃
- **입력 정보**: 현재 로그인 식별 정보
- **필요한 결과**: 로그아웃 완료 여부, 이후 개인 정보 접근 종료

#### 탈퇴 또는 계정 비활성화

- **사용자 동작**: 탈퇴 또는 계정 비활성화
- **입력 정보**: 본인 확인·요청 사유 등 운영 정책상 필요한 정보
- **필요한 결과**: 처리 가능 여부·결과, 접근 종료, 담당 업무 인계 필요 여부

탈퇴는 검토 항목으로 둔다. 기관 계정의 비활성화와 개인 탈퇴 중 필요한 방식을 결정한 뒤 추가한다. 계정 이용 종료가 방문·연계 이력의 즉시 삭제를 뜻하지 않으며 기록 보존·담당자 인계는 기관 정책에 따른다. 회원가입·비밀번호 찾기는 현재 MVP 범위에 포함하지 않는다.

### R02 사용자 및 관리 기능

내 정보·권한·담당 지역, 기관·담당자 목록과 배정 관계를 조회할 수 있어야 한다. 필요한 정보는 사용자 식별 정보·이름·역할·기관·허용 지역·담당자·배정 대상자 수다. 관리자는 허용 지역과 기관 범위에서 현황을 조회하며 모든 개인 상세 열람 권한을 자동 부여하지 않는다.

사용자 등록·수정·비활성화, 담당자 배정 변경은 관리 화면 범위를 합의한 후 후속 기능으로 요청한다. 추가 시 변경 이력·변경자·시각과 허용 권한도 제공한다.

### R03 대상자 조회 및 사례관리

입력 조건은 이름/가상 번호 검색, 행정동·위험등급·혜택 확인 필요·확인 경과 필터, 우선순위·마지막 확인일·다음 확인일 정렬이다. 목록을 나누어 조회할 수 있고 동률 순서는 안정적으로 유지되어야 한다.

목록에는 대상자 식별 정보·표시 이름·가상 여부·담당자·행정동·나이·가구형태·위험점수/등급·마지막 성공 확인일·마지막 연락 시도일·다음 확인일·혜택 확인 필요 여부·근거 요약이 필요하다. 상세에는 허용된 생년월일·주소·연락처·위치·소득취약·건강·현재 수급 여부·확인일과 자료 누락/권한 제한을 추가한다. 실제 대상자 등록·삭제·기본정보 수정은 기관 원장 연계와 업무 범위를 정한 뒤 후속으로 설계한다.

2026년 11월 10일 확정한 혜택 확인 필요 기준은 대상자에게 연결된 혜택 중 지원 상태가 ‘확인 필요’인 항목의 존재 여부입니다. `client_benefits.support_status = 'NEEDS_REVIEW'`인 행이 하나 이상 있으면 true이고, 없으면 false입니다. 연결된 혜택이 없는 대상자도 false입니다. 대상자 목록·상세의 표시와 목록 필터에 같은 조건을 사용합니다.

#### HTTP 계약 정리 (2026-11-15)

| 메서드·경로 | 요청 | 성공 응답의 data |
| --- | --- | --- |
| GET /clients | 검색·필터·정렬·페이지 쿼리 | items, page, page_size, total, queried_at, data_mode |
| GET /clients/{client_id} | 대상자 UUID | 목록의 대상자 정보, 기관·생년월일·주소·마스킹 연락처·좌표·최신 프로필·혜택 상태, queried_at, data_mode |
| GET /clients/{client_id}/history | 대상자 UUID, 종류·기간·페이지 쿼리 | items, page, page_size, total, queried_at, data_mode |

세 경로는 GET 요청이며 본문을 받지 않습니다. 현재 사용자는 인증 계층에서 전달받으며 쿼리에 담당자 ID를 받지 않습니다. 기관·기관과 사용자의 허용 지역 교집합·현재 유효한 배정으로 조회 범위를 제한합니다. 권한 밖 상세·이력은 존재하지 않는 대상자와 함께 404로 응답합니다.

목록 쿼리는 `search`, `region_id`, `risk_grade`, `needs_benefit_review`, `unchecked_days`, `sort_by`, `sort_order`, `page`, `page_size`입니다. 이름·가상 번호는 공백을 제거한 검색어로 부분 검색하며 빈 문자열은 전체 조회입니다. 필터는 모두 AND 조건입니다. `unchecked_days=N`은 마지막 성공 확인이 조회 시각에서 N일을 뺀 시각 이하이거나 성공 확인 이력이 없는 대상자를 조회합니다. `needs_benefit_review`는 생략하면 전체, true/false이면 해당 조건으로 조회합니다.

정렬 기준은 `priority`·`last_success_at`·`next_check_date`이고 방향은 `asc`·`desc`입니다. 기본은 위험점수 내림차순(`priority`, `desc`)이며 모든 정렬에서 null을 마지막에 두고 동률은 대상자 ID 오름차순으로 고정합니다. 페이지는 기본 1, 페이지당 기본 20명·최대 100명입니다. 마지막 페이지 이후의 요청은 200과 빈 items를 반환합니다. total은 권한과 필터를 적용한 전체 인원수입니다.

이력 쿼리는 `event_type`, `from_date`, `to_date`, `page`, `page_size`입니다. 종류는 `CONTACT`, `BENEFIT`, `REFERRAL_REQUEST`, `REFERRAL_STATUS_CHANGE`이며 생략하면 전체입니다. 기간은 한국 날짜 기준 양끝을 포함하고 시작일이 종료일보다 늦으면 422입니다. 발생시각 내림차순·종류 오름차순·이벤트 ID 오름차순으로 정렬합니다. 각 이벤트의 detail에는 체크리스트 답변·혜택 상태 변경 전후·연계 요청 및 처리 내용을 종류에 맞춰 담습니다. 최초 연계 생성 이벤트는 요청과 중복하지 않습니다.

응답은 공통 `data`·`error` 형식입니다. 성공은 error=null, 실패는 data=null이며 error에 code·message·details를 담습니다. R03 오류는 401 `AUTH_REQUIRED`, 404 `CLIENT_NOT_FOUND`, 422 `INVALID_REQUEST`, 503 `SERVICE_UNAVAILABLE`을 사용합니다. 404는 상세·이력에 적용합니다.

개인 자료 안내는 data_mode=`DEMO`로 제공합니다. 일시는 ISO 8601 한국시간(+09:00), 날짜는 YYYY-MM-DD이며 queried_at은 각 요청의 읽기 기준시각입니다. 목록·전체 건수·파생값은 같은 읽기 스냅샷을 사용하고 다음 페이지 요청은 그 시점의 최신 자료를 조회합니다.

담당자는 현재 배정의 `workers` 배열로 제공합니다. 누락·미확인·이용 불가·권한 제한·해당 없음은 값의 null과 `field_info`의 상태·이유·출처·확인일로 구별합니다. 최신 프로필의 빈 값을 과거 revision으로 보충하지 않습니다. 계산 결과가 없는 위험점수·등급은 null로 표시하며 등급 경계와 산식을 임의로 정하지 않습니다. 이전 결과를 표시하면 `risk.stale`과 현재 계산 상태를 함께 제공합니다. 혜택의 지원 상태와 수급 상태는 별도 필드로 유지합니다.

다음 확인일은 occurred_at·created_at·id 내림차순의 최신 연락 기록에서 가져옵니다. 연락 기록 자체가 없으면 조회값은 null입니다. 연락 기록의 next_check_date는 성공·실패·거부 모두 필수이며 통합 이력 DTO도 null을 허용하지 않습니다.

요청·응답의 구체적인 필드는 [client DTO](../dto/client_dto.py), 공통 형식은 [common DTO](../dto/common_dto.py), 예시는 [Swagger](../swagger.yaml)에 작성했습니다. 2026년 11월 15일 handler·service·DB 연결과 공통 오류 처리를 구현했습니다. 기존 스키마와 공통 개발 seed를 넣은 임시 PostgreSQL 18.6에서 API 테스트 19개와 세션·자료 누락·위험결과 세대 등의 추가 검증을 통과했습니다. 라즈베리파이 DB의 버전·스키마·주요 데이터·다음 확인일 제약과 네트워크는 DB 담당이 사용자 실행 출력으로 확인을 마쳤으며 API 컨테이너 연결은 backend 배포 단계에서 검증합니다.

### R04 담당자 대시보드

선택 주간의 담당 수, 위험등급별 인원, 미확인 인원, 방문·전화·모니터링별 큐 건수, 혜택 확인 필요 인원을 조회한다. 같은 시점의 자료로 집계하고 기준시각을 제공한다. 미확인 인원의 정의와 배정 변경 반영 시점은 상세 설계에서 합의한다. 담당자 배정 명단의 업무 집계와 주민 전체 통계는 구분한다.

### R05 방문 및 전화 계획

주간·행정동·연락 방식·검토 상태·업무 진행 상태에 따라 추천 큐를 조회한다. 필요한 결과는 대상자·추천 순위·점수·방식·근거·마지막 확인일·예정일·검토 상태·실행 상태다.

담당자가 대상·연락 방식·예정일시·사유를 입력하여 확정·보류·일정 변경을 할 수 있어야 한다. 확정 시 예정일시, 보류 또는 추천 방식 변경 시 사유가 필요하다. 추천을 자동 확정하지 않는다. 추천/확정/보류와 미진행/확인 완료/연락 실패는 별도 상태로 관리한다. 완료된 업무의 과거 계획을 덮어쓰지 않고 추가 연락은 새 기록으로 남긴다.

### R06 위험점수 및 추천 근거

대상자별 상대적 우선순위 점수와 소득취약·연령독거·건강낙상·동네환경·계절특보·확인경과의 입력값·가중치·기여도·근거·출처·기준일을 제공한다. 전체 점수·등급·산식 버전·계산시각·자료 누락·계산 상태도 필요하다.

계획서의 초기 가중치는 0.25/0.20/0.20/0.15/0.10/0.10이며 정규화·등급 경계·권장 주기는 분석 담당자와 확정한다. 자료 미확인을 위험 없음이나 0점으로 처리하지 않는다. 저장 후 재산출 중·완료·실패를 구분하고 이전 값을 표시하면 이전 계산시각을 유지한다. 점수는 위험 확률이나 자동 선정 결과가 아니다.

### R07 현장 기록 및 체크리스트

현재 체크리스트 항목·선택지·필수 여부·버전을 조회한다. 낙상·냉방·난방·조명·보행·식사·연락망을 점검하며 위험 발견/위험 없음/미확인/해당 없음을 구분한다. 문항의 위험 방향을 통일해 답변 의미가 바뀌지 않도록 한다.

저장 입력은 대상자·관련 계획·방문/전화·확인 일시·성공/실패/거부·체크리스트·위기 여부·메모·다음 확인일·혜택 안내/신청지원·미조치 사유다. 필요한 결과는 저장 완료 여부·기록 식별 정보·갱신된 업무 상태와 확인일·재산출 상태다.

연락 실패·거부는 최근 성공 확인일을 바꾸지 않고 시도일만 별도 기록한다. 연락하지 못한 대상자의 안전 상태를 위험 없음으로 저장하지 않는다. 중복 클릭·재시도에도 같은 기록이 중복 생성되지 않아야 한다. 체크리스트 변경·다른 담당자 수정은 화면에서 알 수 있어야 한다. 메모 2,000자 이하·미래 확인일시 금지를 입력 기준으로 제안한다. 저장 후 큐·혜택·확인일이 일관되게 반영되어야 한다.

#### R07 첫 구현 범위

| 메서드·경로 | 프론트 연동 |
| --- | --- |
| GET /clients/{client_id}/contact-form | 현장 기록 화면을 열 때 호출합니다. 현재 게시 양식의 `checklist_version_id`, `version_code`, `name`, `questions`와 대상자의 `client_version`을 받습니다. 문항에는 `question_id`, `question_code`, `label`, `sort_order`, `is_required`, `allowed_answers`가 있습니다. |
| POST /clients/{client_id}/contacts | 양식의 `client_version`을 `expected_version`으로 보내고, 받고 사용한 양식 ID와 문항 ID를 보냅니다. 같은 저장을 재시도할 때는 요청 키와 입력을 그대로 사용합니다. |

공통 개발 데이터에서 계획에 연결되지 않은 전화 시도 저장 요청의 예시입니다.

```json
{
  "request_key": "19877c81-aa2b-4102-a44d-45f2f6056b40",
  "expected_version": 1,
  "checklist_version_id": "7801d1a1-fb30-5c78-b6eb-6e0e618eeb0f",
  "answers": [
    {"question_id": "5b0a2613-44cf-5cdf-ab95-6eb1cfa5a4c0", "answer_code": "UNCONFIRMED"}
  ],
  "channel": "PHONE",
  "occurred_at": "2026-11-18T10:00:00+09:00",
  "result": "FAILED",
  "crisis_detected": null,
  "memo": "전화 연결이 되지 않았습니다.",
  "next_check_date": "2026-11-20",
  "no_action_reason": "연락 실패"
}
```

저장에 성공하면 `201`과 공통 응답을 반환합니다. `data`에는 저장한 `contact_id`, `client_id`, 변경된 `client_version`, 대상자의 `last_success_at`, `last_attempt_at`, `next_check_date`, `calculation_status`가 있습니다. 날짜는 전체 연락 이력을 기준으로 집계합니다.

```json
{
  "data": {
    "contact_id": "20bb8e15-e92e-447c-8e9b-cdbdcbd3a056",
    "client_id": "21ecb97b-ebc5-5a07-b88d-85511ebe793a",
    "client_version": 2,
    "last_success_at": "2026-11-03T09:00:00+09:00",
    "last_attempt_at": "2026-11-18T10:00:00+09:00",
    "next_check_date": "2026-11-20",
    "calculation_status": "PENDING"
  },
  "error": null
}
```

같은 키와 같은 입력을 재전송하면 기존 접근 권한을 확인하고 최초의 `201`과 응답을 돌려줍니다. 응답을 잃었을 때는 기존 키를 유지합니다. `VERSION_CONFLICT` 또는 `CHECKLIST_VERSION_CONFLICT`가 오면 양식을 다시 불러온 뒤 새 저장 요청을 보냅니다. 같은 키의 입력이 달라지면 `REQUEST_KEY_CONFLICT`입니다. 세 오류는 `409`입니다.

실제 연락 일시는 시간대를 포함하고 미래 일시는 `422`입니다. 다음 확인일은 세 결과 모두 필수이며 실제 연락일(한국 시간) 당일 또는 이후로 지정합니다. 메모는 2,000자까지 받습니다. 실패·거부에서 ‘위험 없음’ 답변을 저장할 수 없습니다. 위기 미확인은 `null`로 보냅니다. 현재 양식은 개발용 문항으로 검증하며 계획 갱신·혜택 행동·프로필 자동 갱신·위험점수 계산은 후속 연결 범위입니다.

### R08 복지혜택 안내 및 신청지원

대상자의 나이·가구형태·행정동·소득취약·현재 수급 정보를 바탕으로 확인할 혜택 후보를 제공한다. 필요한 결과는 혜택명·유형·근거·미확인 조건·신청 가능 시점·필요 서류·대리신청 여부/조건·공식 출처·검토일·규칙 버전·지원 상태다.

담당자는 확인 필요/안내 완료/서류 준비/신청 지원/신청 완료/기관 확인 수급/보류를 기록한다. 보류에는 사유, 기관 확인 수급에는 확인 근거·확인일이 필요하다. 신청 완료와 수급 확정·자격 적격은 구분한다. 진행된 상태를 새 안내 기록 때문에 이전 단계로 되돌리지 않고 행동 이력을 유지한다.

### R09 부서 연계 및 처리 관리

지역·업무 유형에 맞는 연계 기관명·담당 업무·지역·연락 정보를 조회한다. 담당자가 현장 기록·기관·사유·요청 조치·희망일을 입력하면 연계 요청을 등록하고 접수 식별 정보·처리 상태를 확인할 수 있어야 한다.

조회 결과에는 대상자·관련 기록·기관·사유·요청 조치·희망일·요청/접수/완료일·결과·처리 이력이 필요하다. 권한 있는 처리자는 요청→진행→완료 또는 요청/진행→반려로 처리하며 결과·사유·처리자를 남긴다. MVP는 내부 데모 요청이며 실제 외부 발송 여부와 데모 여부를 구분한다.

### R10 지역 현황 및 자원 정보

구·동 목록과 계층·코드 체계·기준일을 제공한다. 지역·기준월별 고령·1인가구·수급 지표, 배정 명단의 고위험 대상수·담당자 부담을 조회한다. 지표마다 값·단위·분자·분모·정의·기준일·출처·누락 상태가 필요하다.

시설은 지역·유형·지도 범위 또는 허용된 대상자 주변으로 조회한다. 시설명·유형·주소·위치·연락처·운영시간·기준일·출처, 가능한 경우 거리와 계산 방식을 제공한다. 같은 주소의 다른 시설은 별도 시설로 유지하고 공유 위치를 구분한다. 좌표가 없으면 목록 조회는 가능해야 한다. 직선거리를 실제 보행시간이나 최적 경로로 표시하지 않는다.

현재 특보에는 종류·단계·발표구역·발표일시·발효/해제·수집 상태·마지막 성공시각이 필요하다. 특보 없음과 수집 실패를 구분한다. 구역과 행정동 대응은 백엔드에서 처리하며 구역 특보를 동별 관측값으로 표현하지 않는다.

### R11 주간 보고 및 성과 집계

주간·권한 있는 담당자/지역 범위로 방문·전화·위기·혜택 발굴·신청지원·연계 요청/완료·미조치 사유를 조회한다. 집계 기간·기준시각·분자/분모·확인율·연계율·접수 소요시간·근거 기록이 필요하다. 인쇄는 프론트에서 구성하며 별도 보고서 파일 생성은 필수가 아니다.

주간 확인율은 시작 시점 점수 상위 20% 집합을 분모로 고정하고 주간 성공 확인한 고유 대상자를 분자로 계산한다. 상위 20%와 HIGH 등급은 별개다. 동률·인원 반올림·배정 변경·결측 제외 기준은 분석 담당자와 확정한다.

방문·전화는 성공 확인 기록 건수, 혜택 발굴은 담당자가 처음 확인한 대상자·혜택 조합 수, 신청지원은 주간 지원한 고유 대상자·혜택 조합 수로 제안한다. 후보 자동 생성만으로 발굴 건수를 올리지 않는다. 연계 요청은 주간 생성, 완료는 주간 완료 건수다. 완료율은 해당 주간 요청 중 조회시점까지 완료된 비율로 제안하며 분모와 시각을 제공한다. 접수 소요시간은 요청→접수 시간이고 미접수 건수는 별도로 표시한다. 분모가 없으면 비율을 0으로 단정하지 않는다. 이동시간·보고시간 감소는 측정 자료가 없으면 미측정이다.
